# 从一句用户偏好读懂记忆系统

这套服务保存“某个用户在什么情境下偏好什么”，保留依据和历史，并根据可归因的结果更新效用。第一轮学习不需要启动向量数据库，也不需要接入付费模型。

面向有一点编程基础、尚不熟悉本项目的读者。先沿一个具体例子观察输入、保存的对象和返回结果，再学习分层与边界；无需先懂向量数据库或 Agent 框架。

## 阅读顺序与完成标志

1. [项目到底解决什么问题](00-why-this-project.md)：用简单偏好表作对照，理解为什么需要来源、版本、Trace 和反馈。
2. [一条偏好如何进入系统](01-write-and-correct.md)：能区分原始证据、记忆记录和不可变修订。
3. [召回、上下文和结果反馈](02-recall-and-feedback.md)：能算一次效用更新，并解释为什么读取不加分。
4. [时间、投影和演化](03-time-projection-evolution.md)：能判断迟到修订和过期向量的处理边界。
5. [启动、排障与练习](04-run-and-practice.md)：亲手跑一个闭环、预测错误，再核对结果。

建议先只读前三篇中的例子，不一次性追完所有类。一次有 30 分钟就完成一个输入变化实验；有 90 分钟再追到存储适配器。

## 先认清三个边界

- 当前主要业务是结构化偏好写入。`key`、`value`、证据和置信度来自请求；不能把它讲成系统自动从任意长对话提取所有记忆。
- 召回会追加 RecallTrace，因此“只读”是指不改变信念与效用，并非数据库零写入。
- “自演化”指受约束策略及实验状态变更，不是微调大模型，也不是自动改变权限规则。
